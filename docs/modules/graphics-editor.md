# Графический редактор

Модуль `editor`, адрес `#editor`. Рисует на HTML canvas размером 1200×720. Позволяет импортировать изображение, рисовать кистью и фигурами, стирать, отменять действия, скачать PNG и сохранять снимки в SQLite.

## Где находится код

| Файл | Ответственность |
| --- | --- |
| frontend/src/modules/Editor.jsx | Холст, инструменты, история, импорт, экспорт, библиотека |
| frontend/src/api/client.js | listProjects, getProject, saveProject и общий HTTP-клиент |
| backend/Controllers/ProjectsController.cs | GET/PUT /api/projects |
| backend/Models/Project.cs | ProjectSummary, Project и SaveProjectRequest |
| backend/Services/ProjectService.cs | Проверка названия, PNG-префикса и размера |
| backend/Data/ProjectRepository.cs | Параметризованные SELECT и INSERT/UPDATE |
| backend/Data/HubDatabase.cs | Соединение SQLite и создание таблицы projects |
| frontend/src/style.css | editor-top, editor-layout, tools, canvas-area |

## Состояние

canvas — ссылка на элемент canvas; origin — начальные координаты и снимок пикселей перед жестом; drawing — идёт ли рисование; history — массив PNG-снимков; cursor — позиция в истории; file — input импорта. Эти значения хранятся в useRef.

tool, color, size — выбранные инструмент, цвет и толщина. name — название проекта, projects — полученный список библиотеки, message — сообщение, busy — ожидание сохранения. Служебный счётчик setRevision обновляет доступность кнопок истории, поскольку изменение ref само по себе не вызывает рендер.

## Основные функции

| Функция | За что отвечает |
| --- | --- |
| saveHistorySnapshot | Добавляет PNG-снимок; удаляет ветку повтора после нового действия; хранит до 25 состояний |
| getCanvasPoint | Пересчитывает координаты указателя из CSS-размера в пиксели холста |
| startDrawing | Захватывает pointer, сохраняет исходные пиксели, начинает линию или ставит точку |
| continueDrawing | Продолжает кисть/ластик либо перерисовывает предварительный контур фигуры |
| finishDrawing | Завершает жест и добавляет состояние истории |
| loadImage | Загружает Image, очищает фон белым, вписывает картинку с сохранением пропорций |
| restoreHistory | Загружает предыдущий/следующий снимок по delta -1/+1 |
| importImage | Создаёт временный URL выбранного файла, загружает картинку, освобождает URL |
| persistProject | Генерирует новый UUID, отправляет PNG в API |
| refreshProjects | Получает список id, name, updated |
| openProject | Загружает PNG конкретного проекта и помещает его на холст |

Экспорт PNG и очистка холста привязаны к соответствующим кнопкам. Очистка просит подтверждение и тоже добавляется в историю. Ластик закрашивает белым: прозрачность не поддерживается.

## Поток данных

```text
Указатель → canvas → toDataURL(PNG) → saveProject
→ PUT /api/projects/{id} → ProjectsController → ProjectService
→ ProjectRepository → SQLite projects
```

JSON запроса: `{ "name": "Рисунок", "content": "data:image/png;base64,..." }`. Каждая кнопка сохранения создаёт новый снимок с новым UUID. API также умеет обновлять существующий id, но интерфейс рисунков использует снимки.

| Метод | Адрес | Результат |
| --- | --- | --- |
| GET | /api/projects | Список без тяжёлого PNG-содержимого |
| GET | /api/projects/{id} | PNG data URL и название; 404, если нет |
| PUT | /api/projects/{id} | Создание/обновление; 400 при некорректных данных |

Таблица projects: id TEXT PRIMARY KEY, name TEXT, content TEXT, updated TEXT. Имя до 200 символов, content до 12 млн символов. PNG-префикс проверяется, полная декодировка изображения сервером не выполняется.

## Ограничения и проверка

Нет слоёв, выделения, обрезки, текста и прозрачного фона. История живёт в браузере и сбрасывается после перезагрузки. Импорт масштабирует изображение под фиксированный холст; PNG хранится в SQLite текстом. Для экспорта сервер не нужен.

Проверьте кисть, точку, ластик, фигуры в разных направлениях, отмену/повтор, импорт JPEG/PNG, экспорт и сохранение/открытие из базы. Переключение раздела не должно стирать рисунок. Проверяйте понятное сообщение при отключённом API.
