# Музыкальный проигрыватель

Модуль `player`, адрес `#player`. Воспроизводит выбранные пользователем аудиофайлы локально: сервер и SQLite не используются. Файлы не отправляются в сеть. Плейлист существует до перезагрузки страницы.

## Что можно делать

Добавлять несколько треков через выбор файлов или перетаскивание; воспроизводить и ставить на паузу; переключать треки, перематывать, менять громкость, включать случайный порядок и повтор текущего трека; удалять треки из списка.

## Где находится код

| Файл | Ответственность |
| --- | --- |
| frontend/src/modules/Player.jsx | Состояние плейлиста, обработчики и интерфейс |
| frontend/src/modules/registry.js | Регистрация под id player |
| frontend/src/style.css | now-playing, record, play-controls, playlist, track; адаптивность и анимация |
| frontend/src/App.jsx | Сохраняет компонент смонтированным при переключении разделов |

Контроллера проигрывателя нет: все действия выполняются через стандартный HTML audio. C# нужен другим модулям.

## Состояние и ссылки на DOM

| Переменная | Что хранит |
| --- | --- |
| tracks | Массив объектов id, title, url, size |
| index | Индекс текущего трека; -1 означает отсутствие выбранного трека |
| playing | Состояние воспроизведения из событий audio |
| time, duration | Текущая позиция и длительность в секундах |
| volume | Громкость от 0 до 1 |
| repeat, shuffle | Повтор трека и случайный выбор следующего |
| error | Сообщение об ошибке формата или воспроизведения |
| audio | useRef на HTML audio: play(), pause(), currentTime, volume |
| input | Скрытый input type=file |
| urls | Созданные Object URL для освобождения при размонтировании |
| autoplay | Нужно ли включить новый src после загрузки метаданных |

useState вызывает обновление интерфейса. useRef хранит DOM-элемент или служебное значение между рендерами без собственного обновления интерфейса.

## Основные функции

| Функция | Действие |
| --- | --- |
| formatTime | Преобразует секунды в минуты:секунды; для неизвестной длительности показывает 0:00 |
| addTracks | Фильтрует аудиофайлы, создаёт Object URL, добавляет записи в tracks |
| playCurrentTrack | Вызывает audio.play() и обрабатывает отклонение Promise |
| selectTrack | Выбирает трек; для нового src устанавливает autoplay и сбрасывает позицию |
| playNextTrack | Выбирает следующий индекс по порядку или случайно; после последнего возвращается к первому |
| removeTrack | Убирает запись, освобождает URL; удаление текущего трека останавливает audio и сбрасывает выбор |

## Как проходит воспроизведение

1. addTracks получает File из input или dataTransfer.files.
2. URL.createObjectURL создаёт временный адрес blob: для доступа браузера к файлу.
3. Выбранный URL попадает в src элемента audio.
4. loadedmetadata задаёт duration; если установлен autoplay, запускает трек.
5. play и pause обновляют playing; timeupdate обновляет ползунок и время.
6. ended включает следующий трек. При repeat используется свойство loop самого audio.
7. Ползунок перемотки задаёт audio.currentTime, а эффект volume — audio.volume.

Декоративная пластинка вращается только при playing. При prefers-reduced-motion анимация отключается. Удаление записи из плейлиста не удаляет файл пользователя.

## Ограничения

Кодеки зависят от браузера: расширение файла не гарантирует воспроизведение. Нет сервера стриминга, анализа тегов, сохранения плейлиста или фоновых напоминаний. Переключение раздела сохраняет музыку, перезагрузка страницы — сбрасывает. Object URL непригодны для хранения в SQLite: после новой сессии они не работают.

## Проверка

Добавьте два WAV/MP3, проверьте play/pause, переключение, перемотку и громкость. Включите повтор, дождитесь конца короткого трека. Выберите случайный порядок. Удалите текущий трек — он должен остановиться; удаление другого не должно ставить текущий на паузу. Переключитесь на другой модуль — звук продолжается. Добавьте повреждённый файл и проверьте сообщение об ошибке.
